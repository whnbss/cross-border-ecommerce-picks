## 它是干什么的

一个自托管的客服工作台：网站实时聊天、邮件、Facebook、Instagram、Twitter、WhatsApp、Telegram、Line、SMS 全部汇到一个收件箱，多坐席协作（私密备注、@提及、标签、快捷回复、自动分配、营业时间自动回复）。内置帮助中心、CSAT 满意度报表，并且**能直接看到 Shopify 订单**——客服一边聊一边查单，这是跨境场景最实用的一点。

## 落地步骤（今天就能跑起来）

```bash
# 1. 前置：Docker + docker compose 可用
docker --version && docker compose version

# 2. 拉代码
git clone https://github.com/chatwoot/chatwoot.git
cd chatwoot

# 3. 准备环境变量（.env.example 在仓库根目录）
cp .env.example .env
# 编辑 .env，至少改这几项：
#   SECRET_KEY_BASE=$(openssl rand -hex 64) 的输出
#   POSTGRES_PASSWORD=自定义
#   REDIS_PASSWORD=自定义
#   FRONTEND_URL=http://localhost:3000

# 4. 初始化数据库（用生产 compose 文件）
docker compose -f docker-compose.production.yaml run --rm rails bundle exec rails db:chatwoot_prepare

# 5. 启动并访问
docker compose -f docker-compose.production.yaml up -d
# 浏览器打开 http://localhost:3000 ，完成首次账号创建
```

`docker-compose.production.yaml` 会起 4 个容器：`rails`（应用，仅监听 127.0.0.1:3000）、`sidekiq`（后台任务）、`postgres`（pgvector/pg16）、`redis`。对外暴露必须加 Nginx/Caddy 反代 + HTTPS。

## 风险与坑

- **License 要看清**：README 写 MIT，但 GitHub API 的 license 字段是 `NOASSERTION`，仓库里存在企业版目录。哪些功能（如 Captain、部分集成）属于付费范围，**交付前必须逐项核对**，别把企业版能力写进免费交付清单。
- **通道资质比代码难**：接 WhatsApp 要走 Meta 官方 API、模板审核、号码资质，不是装完就能用；这部分是资质与流程问题，往往比部署更耗时。
- **数据合规**：聊天记录含姓名、电话、地址、订单，属于个人信息。跨境传输要评估 GDPR / 个保法；自托管虽然数据在自己手里，但**责任也在你手里**（备份、加密、访问审计）。
- **资源与运维**：Postgres + Redis + Sidekiq + 文件存储，单机建议 2C4G 起；队列堆积、磁盘写满是最常见的半夜故障。
- **维护状态**：1,627 个 open issue（大项目常态），2026-11-20 仍在推送，官方 Docker 镜像持续发布，属于健康维护；但 Rails 大版本升级需要跟。
- **别承诺"零成本替代 Zendesk"**：WhatsApp 会话费、模板费、短信费照付，能省的是坐席订阅费。
