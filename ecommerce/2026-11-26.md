## 它是干什么的

网页变更监控。你给一个 URL，它定时抓取、比对内容差异、有变化就通过 Apprise 的 70+ 通道（邮件、Telegram、Discord、Slack、Webhook、JSON 回调）通知你。针对电商它有两个专门功能：**单品页价格与补货检测**（自动抽 HTML 里的价格元数据，带价格历史曲线、上/下限与涨跌幅阈值），以及**浏览器步骤 + 可视化选择器**（先登录、加购物车、点 cookie 同意，再精准框选要盯的区块，需要 Playwright 抓取器）。换新一个亮点是 **AI 变更过滤**：用一句人话写意图，比如"只在价格低于 50 美元时通知我""忽略导航和页脚"，模型逐次判定，把无关的 diff 静默掉。

## 落地步骤（今天就能跑起来）

```bash
# 1. 最快路径：docker compose 起（仓库自带 compose 文件，含可选的 Playwright 抓取器）
git clone https://github.com/dgtlmoon/changedetection.io.git
cd changedetection.io
docker compose up -d

# 或者单容器（注意只绑 127.0.0.1，别裸奔到公网）
docker run -d --restart always -p "127.0.0.1:5000:5000" \
  -v datastore-volume:/datastore --name changedetection.io \
  docker.io/dgtlmoon/changedetection.io

# 2. 打开 http://127.0.0.1:5000 ，Add a URL 贴一个竞品商品页

# 3. 在该 watch 的 EDIT 页勾选 "Re-stock & Price detection for single product pages"
#    设价格上/下限、涨跌百分比阈值；通知填 Telegram / 邮件 / Webhook

# 4. 页面是 JS 渲染的，在 docker-compose.yml 里放开 sockpuppetbrowser 服务，
#    然后在 Fetch 选项里选 Playwright/Chrome 抓取器，再用 Visual Selector 框选价格区块

# 5. 批量：用 Excel 导入整份 URL 清单（带标签分组），或用 REST API / OpenAPI 生成 SDK 自动建 watch
```

## 风险与坑

- **爬取合规是前提，不是免责条款**：README 的免责声明写得很直白——遵守目标网站的 ToS、`robots.txt` 与当地法律的责任完全在你。给客户交付时，把"监控哪些站点"写进合同，别让客户拿它去盯有明显反爬声明的平台。
- **AI 功能会把内容发出去**：启用 LLM 摘要/过滤后，页面 diff 与抽取文本会传给第三方模型服务；README 明确提醒要自行确保符合目标站条款与 GDPR 等隐私法规，**费用也全在你这边**。
- **频率是被封的头号原因**：盯得太勤就是给自己找 IP 封禁。合理间隔（商品页 30 分钟~数小时）+ 每 watch 独立代理，比堆机器管用。
- **误报会比你想的多**：前端渲染的"库存还剩 3 件"、随机推荐位、时间戳都会触发 diff，必须配触发过滤器（正则、CSS 忽略区、jq/JSONPath 精确定位）才有用。
- **Playwright 抓取器要单独开**：默认的快速 HTTP 抓取器处理不了 JS 页面，可视化选择器也依赖它；compose 里那段是注释掉的，得手动放开。
- **维护状态**：382 个 open issue，2026-11-25 仍在推，作者个人维护但迭代稳定，另有付费支持渠道。
