## 它是干什么的

开源 WMS（仓储管理系统）。作者在供应链行业做了 15 年，这套东西的来源是福特亚太售后物流的仓储流程。核心流程齐：ASN 收货、DN 发货、库存、库位、PDA 扫码。架构是前后端分离（DRF + Quasar），前端一套代码能编成 Web、安卓、PDA 甚至小程序——也就是 OneAPP。README 里列的真实改造场景包括 3PL 云仓的多仓集群、货主隔离、冷链温控、药品批次效期，**以及跨境电商的国际物流与报关接口对接**。

## 落地步骤（今天就能跑起来）

```bash
# 1. 后端
git clone https://github.com/GreaterWMS/GreaterWMS.git
cd GreaterWMS
pip install -r requirements.txt
daphne -b 0.0.0.0 -p 8008 greaterwms.asgi:application

# 2. 前端（另开一个终端）
cd templates
npm install
quasar dev

# 3. 前端要指向后端：改 templates/public/statics/baseurl.txt 里的请求地址

# 4. 建库（默认 SQLite 直接可用；生产换 MySQL/PostgreSQL 改 settings）

# 5. PDA/移动端：同一套 Quasar 前端可以编成 Android 与 PDA 程序，按 Quasar 的构建命令输出
```

## 风险与坑

- **3.0 把核心迁到了 Bomiot**：README 明说 3.0 用 Bomiot 框架重建（Rust 插件架构 + 应用市场），**开发者文档也已整体迁移到新仓库**。这意味着本仓库更像发行包与业务模板，二次开发要同时看两个项目——这是当前最大的落地摩擦。
- **WMS 是重实施，不是重安装**：装起来只是第一天。真正的成本在库存初始化、库位规划、作业流程改造、员工培训；没有仓储经验别接这单。
- **二次开发门槛不低**：Django 3.1 + Vue 2.6 的技术栈偏老，新同事上手要时间；前端 Quasar 编译 PDA/安卓需要对应工具链。
- **PDA 硬件适配**：不同品牌扫码枪/手持机的系统版本差异大，现场调试是躲不掉的活。
- **数据责任重**：库存数据错了，客户当天的发货就废了。上线前必须做双轨并行与差异核对。
- **维护状态**：74 个 open issue、2026-10-26 仍在推，社区活跃度中等；商业支持走官网表单。
