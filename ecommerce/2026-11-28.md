## 它是干什么的

自托管的邮件列表与 newsletter 管理器，整个系统打成一个二进制，配一个 PostgreSQL 就能跑，带现代管理后台。联系人名单、邮件活动、模板、SMTP 发送都自己掌控——**发多少封、有多少联系人，都不产生按量费用**。

## 落地步骤（今天就能跑起来）

```bash
# 路线 A：docker compose（最快，一分钟起）
curl -LO https://github.com/knadh/listmonk/raw/master/docker-compose.yml
docker compose up -d
# 打开 http://localhost:9000 ，默认后台走安装引导

# 路线 B：单二进制
# 从 Releases 下载并解压 listmonk
./listmonk --new-config      # 生成 config.toml，填数据库与 SMTP
./listmonk --install         # 初始化 Postgres（升级用 --upgrade，可重复执行）
./listmonk                   # 启动，同样是 9000 端口
```

上线前必须做的三件事：配好 SPF/DKIM/DMARC 记录、用独立子域做发信域（别拿主域试错）、接一个可靠的 SMTP 服务商。

## 风险与坑

- **AGPL 不等于不能用，但要换做法**：卖给最终客户做**私有化部署、连源码一起交付**是合规的；做成"你运营、客户只登录"的多租户 SaaS，就要按 AGPL 开放你的改动。这也是它和 11-27 那次落选 fleetbase 的差别——EDM 的客户本来要的就是"我自己的一套系统"（连源码一起交付），不是租你的服务。
- **送达率是真正的门槛**，不是软件：新域名冷启动要慢慢预热，发信量、退信率、投诉率都会被邮箱服务商盯着。软件装完只完成 20%。
- **你自己的 IP 名声自己负责**：被投诉到黑名单，影响的是你的发信域，恢复要几周。**别用来发未经许可的名单**——这是垃圾邮件，也可能违法。
- **邮件内容有合规要求**：欧盟 GDPR、美国 CAN-SPAM 都要求可退订、真实发件人信息；跨境发给欧洲用户前先确认。
- **运维细节多**：PostgreSQL 备份、SMTP 限流、退信处理都要有人管；一键装好不等于一键运营。
- **维护状态**：71 个 open issue，2026-11-27 仍在推，作者是 Zerodha 背景的开发者，项目长期稳定，但**文档主要在官网 listmonk.app，不在 README 里**。
