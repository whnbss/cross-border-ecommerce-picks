## 它是干什么的

自托管的数据接口：一个 `docker compose up` 起服务，之后用 REST、MCP 或 CLI 三种方式取数据。它不靠你手抄 cookie——身份池由无头浏览器自动"铸"出来并在失效前补池，请求按身份健康度轮转、每个接口独立熔断。抓到的内容全部落 PostgreSQL 归档，**上游把视频删了，你这里还在**。附带离线语音转文字（FunASR，中文）。

## 落地步骤（今天就能跑起来）

```bash
# 1. 前置：Docker + Compose v2（国内拉镜像先配镜像源，README 有专门章节）
docker --version && docker compose version

# 2. 官方引导安装脚本（会问你几个问题、检查 Docker、按机器规格调资源上限）
curl -fsSL https://raw.githubusercontent.com/Evil0ctal/Douyin_TikTok_Download_API/main/install/install.sh -o install.sh
less install.sh        # 先读一遍再执行，好习惯
bash install.sh

# 3. 用安装日志里的 token 创建第一个管理员，然后打开控制台
#    v5 监听 8000 端口：http://<你的IP>:8000
#    API 文档在 /docs，MCP 在 /mcp

# 4. 手动路线（不用脚本时）
git clone https://github.com/Evil0ctal/Douyin_TikTok_Download_API.git
cd Douyin_TikTok_Download_API
# 按 README 写 .env：POSTGRES_PASSWORD / REDIS_PASSWORD / SECRET_KEY（仓库不带任何默认密码）
export COMPOSE_ENV_FILES=.env
docker compose -p dtk -f docker/compose.yml up -d

# 5. 让 AI agent 接进来（可选）
claude mcp add --transport http dtk http://127.0.0.1:8000/mcp/ \
  --header "Authorization: Bearer dtk_YOUR_API_KEY"
```

想省掉首次本地编译，可在 `.env` 里指定官方镜像 `DTK_IMAGE=evil0ctal/douyin_tiktok_download_api` + `DTK_IMAGE_TAG=latest` 再 `pull`，否则 compose 会从 Dockerfile 现场构建（要几分钟）。

## 风险与坑

- **平台条款是最大的雷**：这是抓取第三方平台数据，违反平台 ToS 的概率不低。**只做"看"，不要做"骚扰、倒卖个人信息、批量搬运"**——评论里的用户名就是个人信息。
- **身份池不等于免死**：项目自己写了"平台很少因为读取数据封号，但不能排除"。别用主账号登录态去做高频抓取。
- **版权**：无水印下载拿到的仍是他人作品，二创/商用要授权，否则是侵权而不是"技术问题"。
- **法务边界**：卖给客户的是"数据服务"还是"爬虫软件"，责任不同；合同里把数据来源与使用范围写死。
- **运维成本**：Postgres + Redis + 浏览器容器 + 下载器 + 转录 sidecar，一套下来吃内存；浏览器容器必须本地构建（作者把版本 pin 当安全控制），升级时要重建。
- **维护状态**：21,518★、2,990 fork、只有 4 个 open issue，2026-11-20 仍在推送，作者维护强度很高；但**平台签名算法一变就可能集体失效**，这是这类项目的结构性风险。
