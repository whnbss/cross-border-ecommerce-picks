# ERPNext — 给跨境卖家做 ERP 实施，一单顶半年工资

## 它是干什么的

一套完整的开源 ERP：会计、订单、库存、采购、制造、资产、项目，全部在一个系统里，底层是 Frappe 框架（Python + JS），自带 REST API 和低代码表单/报表能力。对跨境卖家最有用的是**库存与订单链路**：多店铺销量 → 库存预警 → 采购建议 → 到货入库 → 财务对账，一条线打通。

## 落地步骤（今天就能跑起来）

```bash
# 1. 前置：Docker + Docker Compose v2 + git
docker --version && docker compose version

# 2. 官方容器编排仓库（ERPNext 官方 README 指定的安装路径）
git clone https://github.com/frappe/frappe_docker
cd frappe_docker

# 3. 一条命令起演示环境
docker compose -f pwd.yml up -d

# 4. 等 2~5 分钟（看 create-site 容器日志，站点建完才算好）
docker compose -f pwd.yml logs -f create-site

# 5. 打开 http://localhost:8080
#    用户名 Administrator  密码 admin
```

注意 `pwd.yml` 是**一次性演示环境**，官方明确写了 "disposable demo only"、不能装自定义 app。真给客户交付要走 `compose.yaml` 生产编排 + 自定义镜像，见 `frappe_docker` 的 docs 目录。

## 风险与坑

- **GPL-3.0 的边界**：自建自用、给客户在自己服务器上部署通常没问题；但**修改后对外分发**需要开源你的修改。做 SaaS 转售前先找法务确认，别想当然当成 MIT。
- **实施是服务生意，不是软件生意**：客户买的是你把流程理清楚，装个 Docker 不值钱。没有财务/库存背景就别接单。
- **数据迁移最难**：平台订单、Excel 库存、旧系统科目，清洗和映射的工作量常占项目一半以上，报价时必须单列。
- **多平台对接靠开发**：ERPNext 没有开箱即用的亚马逊/Shopify 双向同步，官方生态里有第三方 app，但要评估质量与授权。
- **升级路径**：Frappe 大版本升级（v15→v16）需要专门安排，客户越多越难升；从第一天就要约定版本冻结策略。
- **维护状态**：13,588 个 fork、2026-11-21 仍在推送、官方 Docker 镜像持续发布，是这个方向上最健康的项目之一；但 issue 数量大，遇到问题优先查官方论坛。
