## 它是干什么的

输入是一个长视频（访谈、播客、课程、口播），输出是一整套可直接发布的短视频：自动选段（按平台规则与评分给出至多 10 条合格片段，其余列备选）、自动取景（画面跟说话人，无人镜头给全画幅）、字幕分页、封面、标题、简介、话题，再打成一个 ZIP 发布包。竖版可选"访谈式"或"满屏播客式"，B 站/YouTube 出横版。剪辑、取景、渲染都在本机跑，模型可以选云端 API、Ollama 或 LM Studio。

## 落地步骤（今天就能跑起来）

```bash
# 路线 A：桌面版（最省事）
# 到 Releases 下 macOS .dmg 或 Windows -setup.exe，装好自带 Python 与 FFmpeg
# 首次打开若被拦：macOS 到「隐私与安全性 → 仍要打开」，Windows 点「更多信息 → 仍要运行」
# 设置里填模型服务商与 API Key（或用 Ollama/LM Studio 本地模型），点「用示例项目看看效果」可先不填 Key

# 路线 B：Docker 自建（Linux / 内网 / 想做服务）
git clone https://github.com/zhouxiaoka/autoclip.git
cd autoclip
cp env.example .env
mkdir -p data logs uploads
docker compose up -d --build

# 打开 Web 界面 http://localhost:3000 ，API 文档 http://localhost:8000/docs

# 路线 C：CLI 批量（接自动化）
uvx autoclip-mcp
autoclip produce talk.mp4 --srt talk.srt --platform douyin --portrait-style podcast --json
autoclip outputs PROJECT_ID --export-kits

# 想做 agent 集成：
npx skills add zhouxiaoka/autoclip
```

Linux 上`docker compose` 报目录权限错时，先 `docker compose run --rm --no-deps --user root --entrypoint sh autoclip -c 'chown -R autoclip:autoclip /app/data /app/logs /app/uploads'` 再启动。局域网访问要在 `.env` 的 `AUTOCLIP_ALLOWED_ORIGINS` 填前端地址。

## 风险与坑

- **版权是硬约束**：README 自己的案例库都标注"原片版权归原作者，仅作效果展示"。切片商用必须拿到授权，否则是侵权，不是"技术中立"。
- **自动选段的判断力有限**：它按评分给候选，但"哪条能爆"仍需你复核；README 也建议先看具体失败阶段（转写、模型连接、FFmpeg、候选是否满足平台规则）。别把全自动当免检。
- **费用结构要算清**：软件 MIT 免费，但云端分析/转写/生图按量计费；量大时改本地 Whisper/Ollama 能压成本，代价是慢和吃显存。
- **隐私**：用云端分析会上传字幕与文案，画面理解会上传抽样画面，云端转写会上传音频——客户素材要提前告知并拿到许可。
- **平台限制**：桌面版只覆盖 Apple Silicon 与 Windows x64，Intel Mac 只能用 Docker/CLI；自动投稿需自有 B 站或 Upload-Post 账号。
- **维护状态**：13,441★、2,127 fork、29 个 open issue、当天仍在推送，属活跃；但**个人维护**，作者明确写了"不提供即时客服或一对一部署服务"——你给客户交付时，售后就是你自己的。
